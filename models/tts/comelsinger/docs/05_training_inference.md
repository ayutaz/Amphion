# 05. 学習・推論パイプラインの詳細

## 概要

CoMelSingerの学習・推論パイプラインは、大きく3段階で構成される。
1. **SVT（Singing Voice Transcription）モジュールの事前学習** — ピッチシーケンスを予測するエンコーダのみのTransformerを独立して学習する。
2. **S2A（Semantic-to-Acoustic）モデルのfine-tuning** — MaskGCTフレームワーク上に構築されたS2Aモデルを、CL（対比学習）とSVT監督を用いてfine-tuningする（Algorithm 1）。
3. **推論** — 反復デコーディングによってメル音響トークンを生成し、最終的な波形に変換する。

---

## 1. Algorithm 1 — S2A Fine-tuning with CL and SVT Supervision の完全解説

論文Section III-D（p.7, Algorithm 1）に示されるアルゴリズムの各ステップを以下に詳述する。

### 1.1 前提入力・条件

```
Require:
  θ          : S2Aモデルのパラメータ（LoRAによる一部のみ更新可能）
  f_SVT      : 事前学習済み・凍結されたSVTモデル
  λ_CL       : 対比学習損失の重みベクトル（λ_SCL, λ_FCL を含む）
  λ_SVT      : SVT損失の重み
  λ_mask     : マスク予測損失の重み
  N          : 学習エポック数
  η          : 学習率
  D          : 訓練データセット（歌声録音 + 歌詞 + 音符・ピッチ情報）
```

### 1.2 アルゴリズムの逐次解説

#### Step 1: ミニバッチのサンプリング（Line 2–3）

```
B = {x_1, ..., x_K}  ← D からサンプリング
```

各ミニバッチ `B` は `K` 個の訓練サンプルから構成される。各サンプル `x_i` はアコースティックトークン列・歌詞・ピッチシーケンス・プロンプト音声などを含む。

#### Step 2: セグメント分割（Line 3）

```
S_B^a = S_A  （前半 K_s 個 → セグメント部分 S_A^s）
S_A^f = {x_{K_s+1}, ..., x_K}  （後半 → フルシーケンス部分）
```

バッチを2つのサブセットに分割する。
- **S_A^s（Segment Split）**: 前半 `K_s` 個のサンプル。対比学習のためにシーケンスを複数のセグメントに分割して使用する。
- **S_A^f（Full Sequence）**: 残りのサンプル。完全なシーケンスとして使用する。

この分割は、コース（シーケンス）レベルとファイン（フレーム）レベルという2つの粒度の対比学習を同時に行うために必要である。

#### Step 3: 拡張バッチの構成（Line 4–7）

```
S_B^a = S_A;  S_B^f ← P(S_A^f)  （確率的ピッチ摂動）
B' = S_B^a ∪ S_B^f
a' ← PromptGen(B);  a'^ ← PromptGen(B')
B ← B ∪ a';  B' ← B' ∪ a'^
```

**PromptGen関数の役割**:
- `PromptGen` は各サンプルに対してアコースティックプロンプト `a'` を生成する関数である。
- 具体的には、同一話者の参照音声録音からランダムに切り出したプロンプトセグメントを選択し、S2Aモデルの条件入力として付加する。
- これにより、モデルは話者同一性を保持しながら、歌唱合成時の音色・スタイル情報を参照音声から獲得できる。
- `P(S_A^f)` は確率的なピッチ摂動（pitch perturbation）を適用したフルシーケンスであり、フレームレベルの対比学習において局所的ピッチ変化への感度を高める役割を持つ。

#### Step 4: フォワードパス（Line 8–13）

```
e  ← f_S2A(B);   e' ← f_S2A(B')
eを e_1:K_s（セグメント）と e_{K_s+1:K}（フル）に分割
f^a ← e_{1:K_s};  f^b ← e'_{K_s+1:K}
g^a ← AvgPool(g^a);  g^b ← AvgPool(g^b)
```

- S2Aモデル `f_S2A` にオリジナルバッチ `B` と拡張バッチ `B'` を通し、中間埋め込み `e` と `e'` を得る。
- 埋め込みをセグメント部分（`e_{1:K_s}`）とフル部分（`e_{K_s+1:K}`）に分割する。
- **シーケンスレベルのグローバル表現** `g^a`, `g^b` は AvgPool（平均プーリング）によって時間軸方向に集約して得る（シーケンス全体を1つのベクトルに圧縮）。
- **フレームレベルの局所表現** `f^a`, `f^b` は時間方向の各フレームをそのまま保持する。

#### Step 5: 対比損失の計算（Line 14–16）

```
L_SCL ← f(g^a, g^b) に従って計算（式(3)）
L_FCL ← f(f^a, f^b) に従って計算（式(5)）
L_CL  ← 式(6)に従って計算
```

2種類の対比損失を階層的に計算する（詳細は Section 3 参照）。

#### Step 6: マスク予測とSVT損失の計算（Line 17–22）

```
â   ← f_head(f^a)           （ヘッド経由でフレーム表現を投影）
L_mask ← MaskLoss(â, a)     （マスクされたトークンの再構築損失）
m^p ← f_SVT(StopGrad(â))   （凍結SVTによるピッチ予測）
L_SVT ← f_SVT から m^p と m^p を比較（式(9)）
```

**マスク予測の計算フロー**:
1. S2Aモデルの中間埋め込み `f^a` をデコーダヘッド `f_head` に通し、マスクされたアコースティックトークン位置の予測値 `â` を得る。
2. `MaskLoss(â, a)` : 予測値 `â` と正解のアコースティックトークン `a` との間のクロスエントロピー損失を計算する（MaskGCTの主目的損失）。

**SVT損失の計算フロー**:
1. `StopGrad(â)` : 予測されたアコースティックトークン `â` に対してグラジェントの逆伝播を停止（Stop Gradient）する。これによりSVTモデルへのグラジェントは流れず、S2Aモデルのみが更新される。
2. 凍結済みSVTモデル `f_SVT` に `StopGrad(â)` を入力し、予測ピッチトークン列 `m^p` を得る。
3. `m^p`（SVTが予測したピッチ）と入力の正解ピッチシーケンス `m^p`（ground truth）との間の SVT損失 `L_SVT` を式(9)に従って計算する。
4. この損失により、S2Aモデルが生成するアコースティックトークンが、正しいピッチ軌跡に従うよう間接的に誘導される。

#### Step 7: 全体損失の統合とパラメータ更新（Line 23–24）

```
L ← λ_CL · L_CL + λ_SVT · L_SVT + λ_mask · L_mask
θ ← θ − η · ∇_θ L
```

3種類の損失を各重みで線形結合し、勾配降下法でパラメータを更新する。

## 2. 学習の全体フロー

### 2.1 フェーズ1: SVTモジュールの事前学習

**目的**: 音響トークン列からピッチシーケンスを予測するモジュールを独立して学習し、S2A fine-tuning時の凍結済み補助監督器として利用する。

**アーキテクチャ**:
- エンコーダのみのTransformerベースの軽量モデル。
- 入力: アコースティックコードブック（MaskGCT）から得られるアコースティックトークン列 `a`。
- 出力: 対応するピッチトークン列 `m^p`（フレームレベル）。
- 隠れサイズ12トークン、アテンションヘッド数8、bidden size 512で構成される。

**学習目標 (L_SVT)**:
SVTモジュールは以下の3つの損失を統合した複合損失で最適化される（論文式(9)）:

```
L_SVT = L_CE + λ_seg · L_seg + λ_dur · L_dur
```

- **L_CE（クロスエントロピー損失）**: 各フレームにおいてソフトマックス出力からピッチトークンを予測する主目的損失。
- **L_seg（セグメント遷移損失）**: ピッチ境界をまたぐ遷移でのコントラストを強化する損失（式(7)）。ピッチ境界インジケータ `b_t` を利用し、境界での急激な変化と境界内の連続性を両立させる。
  ```
  L_seg = Σ_{t=2}^{L} [ (1-b_t) · ||p_t - p_{t-1}||^2
                        + b_t · max(0, δ - ||p_t - p_{t-1}||^2) ]
  ```
  ここで `δ` はピッチ境界での最小非類似度を規定する固定マージン。
- **L_dur（ソフト持続時間損失）**: 各ピッチトークンの時間的分布を音響トークンの割り当てセグメント長と整合させる損失（式(8)）。
  ```
  L_dur = Σ_{i=1}^{S} ( Σ_{t=T_i}^{T_i+a_i^d-1} p_t[m_i^p] - a_i^d )^2
  ```
  各ピッチトークン `m_i^p` に割り当てられたセグメント長 `a_i^d` にわたるソフトマックス確率の累積和が実際の長さに近づくよう促す。

**SVTの重みλ**:
- `λ_seg = 3`
- `λ_dur = 5`

**学習データ**:
- M4Singer、Opencpop、MIR-ST500の組み合わせで学習。
- MIR-ST500（50万曲以上のアノテーション付き）で事前学習後、M4Singer+Opencpopの結合データセットでfine-tuningすると最良性能を達成（Table VI参照）。

**事後処理**: SVTの学習完了後、そのパラメータは完全に凍結（frozen）される。以降のS2A fine-tuning中、SVTはグラジェントが流れない推論専用の固定監督器として機能する。

### 2.2 フェーズ2: S2AモデルのFine-tuning（MaskGCTフレームワーク上）

**ベースモデル**: MaskGCT [論文参照18] の事前学習済みS2Aモデル。MaskGCTは非自己回帰型マスク生成モデリングフレームワークであり、以下の特徴を持つ。
- 反復的なデノイジング（masked token reconstruction）によって音響トークンを並列生成する。
- モデルは `p(a | â_mask, a'_ctx, e_text, e_pitch)` を近似し、マスクされたアコースティックトークン位置を、音声プロンプト・テキスト埋め込み・ピッチ埋め込みを条件として再構築する。

**Fine-tuningの目的損失（3成分の統合）**:

```
L = λ_CL · L_CL + λ_SVT · L_SVT + λ_mask · L_mask
```

各成分の役割:
1. **L_mask（マスクトークン予測損失）**: ランダムにマスクされたアコースティックトークンをノイジー入力から再構築するクロスエントロピー損失。MaskGCTの主目的損失であり、歌声の基本的な音響品質を担保する。
2. **L_CL（対比学習損失）**: プロンプトからのプロソディリーケージを抑制しつつ、メロディ条件との整合性を高める（Section 3参照）。
3. **L_SVT（SVT損失）**: 生成されたアコースティックトークンが正しいピッチ軌跡に対応するよう誘導する補助損失。

---

### 2.3 LoRAの適用詳細

**問題意識**: MaskGCTの全パラメータをfine-tuningすることは計算コストが高く、少量の歌唱データでの過学習リスクも存在する。

**LoRA（Low-Rank Adaptation）の仕組み**:
- S2Aモデルのアテンション投影レイヤーにのみ低ランク行列を挿入する。
- 元の重み行列 `W ∈ R^{d×d}` を凍結し、更新可能な低ランク分解 `ΔW = BA`（`B ∈ R^{d×r}`, `A ∈ R^{r×d}`, `r << d`）のみを学習する。
- DiffLlama形式のLoRAを採用（論文Section IV-B参照）。

**適用対象**:
- S2Aモデルの各Transformerブロック内のアテンション投影レイヤー（クエリ・キー・バリュー・出力の各線形投影）。
- ランクパラメータ: `r = 16`、スケーリング係数 `α = 32`（DiffLlama標準設定）。
- アテンションヘッド数: `n = 32`、アテンション次元: `n_c = 32`。

**凍結されるパラメータ**:
- MaskGCTのS2Aデコーダのすべての元の重みは凍結。
- SVTモデルの全パラメータは凍結（`f_SVT` はAlgorithm 1のLine 20で `StopGrad` を適用）。
- テキスト埋め込みモジュールおよび音声VQコードブックのパラメータも凍結。

**更新されるパラメータ**:
- 各アテンション層に挿入された低ランク行列 `B` および `A`。
- ピッチ埋め込み層 `e_pitch`（ピッチシーケンス `m^p` を埋め込みベクトルに変換する層）。
- 長さ予測器（Length Expander / Duration Predictor）のパラメータ。

## 3. 損失関数の全体構成

### 3.1 全体損失式

```
L = λ_CL · L_CL + λ_SVT · L_SVT + λ_mask · L_mask
```

さらに展開すると:

```
L_CL  = λ_SCL · L_SCL + λ_FCL · L_FCL

L_SVT = L_CE + λ_seg · L_seg + λ_dur · L_dur
```

### 3.2 各損失成分の詳細

#### L_mask（マスクトークン予測損失）

MaskGCTの標準マスク生成モデリング損失。ランダムマスクされたトークン位置について、ノイジーなアコースティックトークン入力 `â` と参照プロンプト・テキスト・ピッチ条件から正解トークン `a` を予測するクロスエントロピー損失。

#### L_SCL（シーケンスレベル対比学習損失）

論文式(3):
```
L_SCL = 1/(2N) Σ_k [ log( exp(g_k^a · g_k^b / τ) / Σ_{j≠k} exp(g_k^a · g_j^b / τ) )
                     + log( exp(g_k^b · g_k^a / τ) / Σ_{j≠k} exp(g_k^b · g_j^a / τ) ) ]
```

- `g^a`, `g^b`: AvgPoolによって得られたシーケンスレベルのグローバル埋め込みベクトル（`∈ R^{N×D}`）。
- `τ`: 温度ハイパーパラメータ。
- 同一サンプルのオリジナル版と摂動版を正例ペア、異なるサンプル同士を負例として対比する。
- **役割**: 同一話者の歌声全体のグローバルな音色・スタイル一貫性を確保し、プロンプトからの話者同一性の漏れ込みを防ぐ。

#### L_FCL（フレームレベル対比学習損失）

論文式(5):

```
L_FCL = 1/(2LN) Σ_k Σ_t [ log( exp(f_{k,t}^a · f_{k,t}^b / τ) / Σ_{j≠k} exp(f_{k,t}^a · f_{j,t}^b / τ) ) + ... ]
```

- `f^a`, `f^b`: 各フレームの時系列埋め込み表現。
- ピッチ摂動を施したシーケンス `P(S_A^f)` と元のシーケンスを比較することで、フレームレベルでの局所的ピッチ整合性を学習する。
- **役割**: 細粒度のメロディ制御を強化し、急激なピッチ変化を含む楽節でも正確な音程再現を実現する。

#### L_CL（統合対比損失）

論文式(6):
```
L_CL = λ_SCL · L_SCL + λ_FCL · L_FCL
```

#### L_CE（SVTクロスエントロピー損失）

SVT内の各フレームで、ソフトマックスから得られるピッチトークン分布と正解との標準クロスエントロピー損失。

#### L_seg（SVTセグメント遷移損失）

論文式(7)（詳細は Section 2.1 参照）。

#### L_dur（SVTソフト持続時間損失）

論文式(8)（詳細は Section 2.1 参照）。

### 3.3 損失重みの一覧（ハイパーパラメータ）

| 係数 | 値 | 対象損失 | 役割 |
|------|-----|---------|------|
| λ_SCL | 0.5 | L_SCL | シーケンスレベル対比損失の寄与 |
| λ_FCL | 1.0 | L_FCL | フレームレベル対比損失の寄与（より重視） |
| λ_SVT | 0.1 | L_SVT | SVTピッチ監督の寄与（補助的） |
| λ_mask | 0.3 | L_mask | マスクトークン予測損失の寄与 |
| λ_seg | 3 | L_seg（SVT内） | セグメント遷移損失の強調 |
| λ_dur | 5 | L_dur（SVT内） | 持続時間損失の強調 |

> **注記**: `λ_FCL > λ_SCL` という設定により、局所的なピッチ変化のモデリング（フレームレベル）をグローバルな音色整合（シーケンスレベル）より相対的に重視している。`λ_SVT = 0.1` と小さい値に設定されているのは、SVT損失が主目的損失ではなく補助的な誘導信号であるためである。

## 4. 推論パイプライン

### 4.1 全体フロー

推論時の入力と出力の関係を以下に示す:

```
入力:
  - 歌詞（lyric）
  - ピッチシーケンス m^p（外部楽譜から取得）
  - 音符デュレーション情報 d
  - 参照音声プロンプト a'（話者同一性のため）

処理:
  T2S → m（セマンティックトークン列） ← テキストから
  S2A（反復デコーディング） → â（アコースティックトークン列）

出力:
  波形 w ← D_A（アコースティックコーデックデコーダ）によって復元
```

### 4.2 T2Sステージ（テキスト→セマンティックトークン）

- **T2S（Text-to-Semantic）モデル**: 歌詞を入力としてセマンティックトークン列 `m` を生成する。
- セマンティック語彙 `V_sem` および長さ `L` のトークン列を自己回帰的に生成。
- 推論では **明示的なDuration Predictor** を使用する: モデルは明示的に学習された音符デュレーション情報 `d` を参照してアコースティックトークン列の長さを決定し、Length Expander によってフレームレベルのデュレーション列 `a^d` を計算する。
  ```
  a^d = [a_1^d, ..., a_S^d]  （各音符の持続フレーム数）
  D = Σ_{j=1}^{S} a_j^d  （総フレーム数）
  ```
- これにより外部から明示的に音符長を制御でき、リズム整合性が保証される。

### 4.3 S2Aステージ（セマンティック→アコースティック）：MaskGCTの反復デコーディング

論文のMaskGCTフレームワーク[18]に基づく非自己回帰型反復デコーディングを採用する。

**反復デコーディングの手順**:
1. **初期化**: 全アコースティックトークン位置を `[MASK]` で埋める。
2. **反復 t = 1, 2, ..., T_iter**（T_iter回繰り返す）:
   a. 現在のマスク状態 `â_t` と条件（セマンティックトークン `m`、プロンプト `a'`、ピッチ埋め込み `e_pitch`）をS2Aモデルに入力。
   b. 各マスク位置について、アコースティックコードブック上の確率分布を計算。
   c. 信頼スコア（confidence score）の高い位置から順に逐次的にアンマスクする（スケジュールに従う）。
3. **最終出力**: 全位置がアンマスクされた時点でアコースティックトークン列 `â` が確定する。

**ピッチシーケンスの外部入力**:
- 推論時、ピッチシーケンス `m^p` は楽譜（MusicXML等）から直接取得した外部入力として与えられる。
- 訓練時と異なり、ピッチ値はSVTモジュールによって予測されるのではなく、外部から明示的に指定される。
- フレームアライメント済みピッチシーケンス `m^p_aligned` は以下の式で導出される（論文Section III参照）:
  ```
  k_{n,i} = k_{n-1,i} + L · round(D · c_i)
  c_i = d_i / Σ_j d_j   （正規化された相対デュレーション）
  ```
  ここで `L` はアコースティックトークン列全体のフレーム数、`D` はデュレーションの総和。
- このピッチシーケンスは S2A モデルのピッチ埋め込み層 `e_pitch` に入力され、各フレームのアコースティックトークン生成を条件付ける。

### 4.4 波形の復元

- MaskGCTの事前学習済みアコースティックコーデックデコーダ `D_A`（BigVGANベース）を用いて、アコースティックトークン列 `â` から最終的な波形 `w` を復元する。
- `D_A` のパラメータはfine-tuning中も凍結されており、音声品質を担保するコーデック表現はそのまま使用される。

### 4.5 推論時の非自己回帰性による効率化

- MaskGCTの反復デコーディングにより、自己回帰型モデルに比べて大幅に推論速度が向上する。
- 論文では推論レイテンシ削減のために非自己回帰型（NAR）デコーディングを採用していることを明示的に述べている（論文p.2右段落）。

## 6. 学習・推論パイプラインの全体図（テキスト図解）

```
[学習フェーズ]

  Step 1: SVT事前学習
  ─────────────────────────────────────────────────────────────
  アコースティックトークン a  →  [ SVTモデル ]  →  ピッチトークン m^p
                                  ↑
                  L_SVT = L_CE + 3·L_seg + 5·L_dur
  ─────────────────────────────────────────────────────────────

  Step 2: S2A Fine-tuning（Algorithm 1）
  ─────────────────────────────────────────────────────────────
  訓練データ D
       ↓ ミニバッチB（K個）
  [PromptGen] → プロンプト a'
       ↓ 分割: S_A^s (前半K_s) + S_A^f (後半)
  [ピッチ摂動P] → 拡張バッチ B'
       ↓
  [S2Aモデル（LoRA適用）]
   ├─ e, e' : 中間埋め込み取得
   ├─ g^a, g^b : AvgPool → シーケンス埋め込み
   ├─ f^a, f^b : フレーム埋め込み
   ├─ L_SCL（式3） ← g^a, g^b
   ├─ L_FCL（式5） ← f^a, f^b
   ├─ â : デコーダヘッドでマスク予測
   ├─ L_mask : MaskLoss(â, a)
   └─ StopGrad(â) → [凍結SVT] → m^p
                              → L_SVT（式9）
       ↓
  L = 0.5·L_SCL + 1.0·L_FCL + 0.1·L_SVT + 0.3·L_mask
       ↓
  パラメータ更新（AdamW, lr=1e-5, 100エポック, 4×RTX A5000）
  ─────────────────────────────────────────────────────────────

[推論フェーズ]

  外部楽譜（ピッチ m^p + デュレーション d）
  歌詞（lyric）
  参照音声プロンプト a'
       ↓
  [T2Sモデル] → セマンティックトークン m
  [Length Expander / Duration Predictor] → フレームデュレーション a^d
       ↓
  [S2Aモデル（MaskGCT反復デコーディング）]
      ← ピッチ埋め込み e_pitch（from m^p）
      ← セマンティック埋め込み（from m）
      ← プロンプト埋め込み（from a'）
       ↓
  アコースティックトークン â
       ↓
  [コーデックデコーダ D_A（BigVGAN, 凍結）]
       ↓
  歌声波形 w
```
