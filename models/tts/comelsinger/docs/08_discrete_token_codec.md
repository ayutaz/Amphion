## 1. ニューラル音声コーデック技術

### 技術的背景

従来の音声圧縮は MP3 や AAC のような知覚符号化（perceptual coding）に依拠していた。これらはマスキング効果などの心理音響モデルを利用するが、ニューラルネットワークを用いた生成モデルとの親和性が低かった。

2021年以降、ニューラルネットワークを用いた **ニューラル音声コーデック**（Neural Audio Codec）が登場し、以下の特性を実現した。

- **離散的なトークン列**として音声を表現 → 言語モデルへの入力として利用可能
- **残差ベクトル量子化（RVQ: Residual Vector Quantization）**による階層的な情報圧縮
- 高品質な音声再構成（音声波形の忠実な復元）

---

### 1.1 SoundStream (Google)

**論文**: "SoundStream: An End-to-End Neural Audio Codec" (Zeghidour et al., 2021, NeurIPS)

#### 概要

SoundStream はGoogleが提案した最初の実用的なニューラル音声コーデックであり、エンドツーエンドのニューラルネットワークで音声を離散トークンに変換する先駆的な研究。

#### 技術的詳細

**アーキテクチャ構成**:
- **エンコーダ**: 畳み込みニューラルネットワーク（ConvNet）で音声波形を潜在表現に変換
- **残差ベクトル量子化器（RVQ）**: 複数段のコードブックで階層的に量子化
- **デコーダ**: 量子化された離散コードから音声波形を再構成

**RVQ（残差ベクトル量子化）の仕組み**:
```
入力音声波形 x
  ↓ エンコーダ
連続潜在ベクトル z

[RVQ第1段] z → 最近傍コードブックエントリ c₁ を選択
           残差: r₁ = z - c₁

[RVQ第2段] r₁ → 最近傍コードブックエントリ c₂ を選択
           残差: r₂ = r₁ - c₂

... (n段繰り返し)

最終コード: (c₁, c₂, ..., cₙ)  ← 各段の離散インデックス
  ↓ デコーダ
再構成音声波形 x̂
```

各段のコードブックは前段の「残差」（誤差）を順次補正するため、多段化することで量子化誤差が指数的に減少する。

**主要パラメータ**:
- サンプリングレート: 24 kHz
- ビットレート: 3 kbps ～ 18 kbps（コードブック数・次元数で調整）
- コードブックサイズ: 各1024エントリ

**訓練目的**:
- 再構成損失（波形レベル + スペクトログラムレベル）
- 敵対的損失（GAN: 識別器を用いた高品質化）
- コミットメント損失（量子化の安定化）

#### 技術的意義

SoundStream は「音声をトークン列として扱う」という発想の原点であり、後続のEnCodec、DACに直接影響を与えた。RVQによる階層的離散化は、粗い意味情報（低段コード）から細かい音響詳細（高段コード）への情報階層を自然に形成する。

---

### 1.2 EnCodec (Meta)

**論文**: "High Fidelity Neural Audio Compression with Improved RVQGAN" (Défossez et al., 2022)
**arXiv**: 2210.13438

#### 概要

Meta（旧Facebook AI）が開発したニューラル音声コーデックで、**CoMelSingerが直接採用している音声圧縮技術**。SoundStreamの改良版として、より高品質な音声再構成と多ビットレート対応を実現。

#### アーキテクチャ詳細

**エンコーダ-デコーダ構造**:
```
音声波形 (24 kHz)
  ↓
EnCodec エンコーダ
  ↓
8段 RVQ (各コードブック 1024エントリ)
  ↓
8個の離散トークン列 (各フレームあたり)
  ↓
EnCodec デコーダ
  ↓
再構成音声波形
```

**8コードブック構造の意義**:

| コードブック番号 | 保持する情報 |
|:---:|:---|
| 第1段 (最上位) | 大局的な音響構造・話者アイデンティティ・内容 |
| 第2〜4段 | 音色・韻律・発話スタイル |
| 第5〜8段 (最下位) | 微細な音響詳細・高周波成分・音質 |

この階層構造により：
- **上位コードのみ**使用 → 低品質だが意味的に正確な音声
- **全コードブック**使用 → 高品質な音声再構成

**技術的改良点（SoundStreamからの進歩）**:
1. **ストリーミング対応**: 低レイテンシー推論をサポート
2. **LanguageModel損失**: トランスフォーマーベースのエントロピー符号化
3. **多周波数スペクトログラム損失**: 異なる時間-周波数解像度での再構成品質向上
4. **量子化のドロップアウト**: 単一モデルで複数ビットレートに対応

**主要パラメータ**:
```
入力サンプリングレート: 24 kHz
フレームレート: 75 Hz（1フレーム = 320サンプル = 13.3 ms）
コードブック数: 8
コードブックサイズ: 各1024エントリ (10ビット)
ビットレート: 1.5 kbps (1コードブック) ～ 12 kbps (8コードブック)
```

**CLAUDE.mdでの記述**:
> Audio codec: EnCodec (8 RVQ codebooks)

#### CoMelSingerでの利用

CoMelSingerのS2Aモジュール（Semantic-to-Acoustic）はEnCodecを音響トークナイザとして使用する。

```
論文 Section III.A より:
"...regulated pitch tokens m^p is derived from the pitch
(m^p, and from the m^p) codebooks following the MaskGCT
setup, and the final waveform w^ is reconstructed from 
acoustic tokens via the decoder D_A."
```

具体的な処理フロー:
```
歌詞テキスト + F0（ピッチ）情報
  ↓ T2S モジュール
セマンティックトークン列 s

セマンティックトークン + ピッチトークン + 音響プロンプト
  ↓ S2A モジュール（MaskGCT拡張）
音響トークン列 a = E_A(w)  ← EnCodecエンコーダ出力

音響トークン列 a
  ↓ EnCodecデコーダ D_A
音声波形 ŵ
```

EnCodecが離散トークン化を担うことで、S2Aモデルは**分類問題**（各フレームでどのコードブックエントリを選ぶか）として音声生成を定式化できる。これが自己回帰/非自己回帰の言語モデルを音声合成に適用できる理由である。

### 1.3 DAC (Descript Audio Codec)

**論文**: "High-Fidelity Audio Compression with Improved RVQGAN" (Kumar et al., 2023)
**arXiv**: 2306.06189

#### 概要

Descript社が開発したニューラル音声コーデックで、EnCodecと同等以上の品質を達成しながら、オープンソースで公開された。44.1 kHz の高サンプリングレートにも対応。

#### EnCodecとの比較・技術的差異

| 特徴 | EnCodec | DAC |
|:---|:---|:---|
| サンプリングレート | 24 kHz | 44.1 kHz |
| コードブック数 | 8 | 12 |
| 量子化改良 | 標準RVQ | コードブック正規化 + ランダムプロジェクション |
| 損失関数 | 多周波数スペクトログラム | 同上 + 追加の識別器 |
| ライセンス | 非商用 | MIT (オープン) |

**DACの技術的革新**:
1. **コードブック使用率の改善**: エントロピー正則化によりコードブックの各エントリが均等に使われる
2. **量子化ドロップアウト**: 推論時に任意のコードブック数を選択可能
3. **より安定した訓練**: 勾配スケーリングの改良

#### 音声合成分野での意義

DACは多くの後続研究でEnCodecの代替として使用されており、両者は現在の離散トークンベースTTSの標準的な音響トークナイザとなっている。CoMelSingerはEnCodecを採用しているが、DACとの互換性も原理的には可能。

## 2. 離散トークンベース音声生成モデル

### 技術的背景

GPT等の大規模言語モデル（LLM）の成功を受け、音声を「トークン列」として扱い、LMと同様のアーキテクチャで音声生成を行うアプローチが急速に発展した。

**離散トークンTTSの基本パラダイム**:
```
テキスト/プロンプト
  ↓ 言語モデル (自己回帰 or 非自己回帰)
音響トークン列
  ↓ ニューラルコーデックデコーダ
音声波形
```

---

### 2.1 VALL-E (参考文献[45])

**論文**: "Neural Codec Language Models are Zero-Shot Text Speakers" (Wang et al., 2023)
**arXiv**: 2301.02111  
**所属**: Microsoft

#### 概要

VALL-E は最初の大規模ニューラルコーデック言語モデルベースTTSであり、**3秒の音声プロンプトのみでゼロショット話者適応を実現**した画期的研究。60,000時間以上の英語音声データで訓練。

#### アーキテクチャ

VALL-E は2段階の自己回帰生成を採用:

**Stage 1: AR（自己回帰）モデル**
```
入力: テキストトークン + 音響プロンプト（第1コードブック）
出力: 第1コードブックトークン列（自己回帰生成）

モデル: GPT-likeなTransformer (LLM)
```

**Stage 2: NAR（非自己回帰）モデル**
```
入力: テキスト + 音響プロンプト（全コードブック） + 第1コードブック列
出力: 第2〜8コードブックトークン（並列生成）

モデル: 条件付き非自己回帰Transformer
```

#### 技術的詳細

**コンテキスト学習（In-Context Learning）**:
VALL-E は音声プロンプトをコンテキストとして取り込み、同一話者の音声を生成する。これはGPTのfew-shot学習と類似のメカニズム。

**EnCodecの活用**:
- 音声をEnCodecで8段RVQトークンに変換
- 第1段コードブック = AR生成（自己回帰、最も重要な音響構造）
- 第2〜8段コードブック = NAR生成（条件付き並列生成）

```
音響トークン階層:
[c₁,₁] [c₁,₂] ... [c₁,T]   ← AR生成（順次）
[c₂,₁] [c₂,₂] ... [c₂,T]   ← NAR生成（並列）
...
[c₈,₁] [c₈,₂] ... [c₈,T]   ← NAR生成（並列）
```

#### 限界と後続研究への影響

- 生成安定性が低い（繰り返しやスキップが発生）
- 長文生成が困難
- 自己回帰生成のため推論が遅い

これらの限界がVALL-E 2、VALL-E R、さらにはCoMelSingerのような非自己回帰アプローチへの研究動機となった。

#### CoMelSingerとの関係

CoMelSinger論文はVALL-E を「最初の大規模LMベースTTS」として位置付け、後続する離散トークンTTSの源流として参照している（Section I.）。VALL-E のコンテキスト学習パラダイムはCoMelSingerのゼロショット話者適応の基本思想を共有している。

---

### 2.2 VALL-E 2 (参考文献[46])

**論文**: "VALL-E 2: Neural Codec Language Models are Human Parity Zero-Shot Text to Speech Synthesizers" (Chen et al., 2024)
**arXiv**: 2406.05370  
**所属**: Microsoft

#### 概要

VALL-E 2 はVALL-E の改良版で、**英語TTSにおいて初めて人間同等（human parity）の品質を達成**したと主張する研究。主要な技術的改良点は Grouped Code Modeling と Continuous Beam Search。

#### 技術的改良

**1. グループコードモデリング（Grouped Code Modeling）**:
複数の音響コードフレームをグループとして扱い、自己回帰生成の効率を向上。

```
従来のVALL-E（フレーム単位自己回帰）:
[c₁] → [c₂] → [c₃] → ... → [cT]

VALL-E 2（グループ単位自己回帰）:
[c₁,...,cG] → [cG+1,...,c2G] → ... → [c(n-1)G+1,...,cT]
```

これにより：
- シーケンス長を G分の1に短縮 → 計算効率向上
- 長距離依存性の学習が容易になる

**2. 連続ビームサーチ（Continuous Beam Search）**:
- 推論時の繰り返し・スキップ問題を軽減
- 複数の生成候補を並列に追跡し、最良を選択

#### CoMelSingerとの関係

VALL-E 2 はゼロショットTTSの品質基準を引き上げた。CoMelSingerは同様のゼロショット話者適応を歌声合成ドメインで実現しようとしており、VALL-E 2 の成果を歌声に拡張する位置付けを持つ。

### 2.3 VALL-E R (参考文献[47])

**論文**: "VALL-E R: Robust and Efficient Zero-Shot Text-to-Speech Synthesis via Monotonic Alignment" (Han et al., 2024)
**arXiv**: 2406.07855  
**所属**: Microsoft

#### 概要

VALL-E R は**音節レベルの単調アライメント（Monotonic Alignment）**を導入することで、VALL-E の安定性問題を根本的に解決した改良版。

#### 技術的革新

**単調アライメントの導入**:
```
テキスト: [t₁] [t₂] [t₃] [t₄] [t₅]
            ↕    ↕    ↕    ↕    ↕
音響フレーム: [aaaaa][bbb][cccccc][dd][eeeee]
```

各音節（テキストトークン）が対応する音響フレーム範囲を明示的に制約することで：
- 音節の繰り返し・スキップを防止
- より安定した長文生成を実現
- アライメント情報を活用した条件付け生成

**効率化技術**:
- コードブックの圧縮とグループ化で推論速度を向上
- 連続パイプラインとして複数のサブタスクを統合

#### CoMelSingerとの関係

VALL-E R の単調アライメント手法はCoMelSingerのSVT（Singing Voice Transcription）モジュールの設計思想と共鳴している。CoMelSingerも歌声においてピッチトークンと音響フレームの明示的アライメントを重視しており、VALL-E R の問題意識（自己回帰モデルの不安定性への対処）を非自己回帰枠組みで解決している。

### 2.4 SoundStorm (参考文献[20])

**論文**: "SoundStorm: Efficient Parallel Audio Generation" (Borsos et al., 2023)
**arXiv**: 2305.09636  
**所属**: Google DeepMind

#### 概要

SoundStorm は**並列デコーディング**を音響トークン生成に適用し、VALL-E 型の自己回帰モデルより大幅に高速な推論を実現した。マスク付き生成モデル（Masked Generative Model）の音声版。

#### アーキテクチャ

**RVQコードブック階層の並列処理**:
```
生成プロセス:
[反復1] 全コードブック・全フレームをマスクした状態から開始
         最も確信度の高いトークンを「アンマスク」
[反復2] 残りのマスクされたトークンを再予測・アンマスク
...
[反復T] 全トークンが確定するまで繰り返し
```

**MaskGIT（Masked Generative Image Transformer）の音声適用**:
- 画像生成で成功した並列マスク生成を音声に適用
- コードブック間の依存関係を考慮した階層的処理

**処理速度**:
- VALL-E 比で約100倍の推論高速化を達成
- RTF（Real-Time Factor） < 1 を実現（リアルタイム以下の推論）

#### 技術的詳細

**コンフィデンス基準アンマスキング**:
各ステップで、モデルが最も自信を持つ（確率が高い）トークンからアンマスクしていく戦略。これにより品質を維持しながら少ない反復で全トークンを確定できる。

**コードブック間の依存性**:
```
第1コードブック（最重要）: 先に生成
  ↓（条件として）
第2コードブック: 第1を条件に並列生成
  ↓（条件として）
...（階層的に下位コードブックを生成）
```

#### CoMelSingerとの関係

SoundStorm の並列デコーディング思想はCoMelSingerが採用するMaskGCT（非自己回帰マスク生成）の直接的な前身技術。CoMelSingerはSoundStormのアプローチを歌声合成に特化させ、さらにピッチ制御と対照学習を組み合わせた。

---

### 2.5 SoCodec (参考文献[30])

**論文**: "SoCodec: A Semantic-Ordered Multi-Stream Speech Codec for Efficient Language Model Based Text-to-Speech Synthesis" (Ye et al., 2024)

#### 概要

SoCodec は**セマンティック情報を優先的に保存するコーデック設計**（semantic-oriented codec）で、離散トークン列の意味的な順序構造を明示的に最適化した研究。

#### 技術的革新

**標準RVQとの根本的な違い**:
```
標準RVQ（EnCodec方式）:
  量子化の目標: 再構成誤差の最小化
  コードブック間の情報: 暗黙的・不規則
  
SoCodec:
  量子化の目標: 再構成誤差 + セマンティック一貫性
  コードブック間の情報: 明示的に意味順に整理
```

**セマンティック監視付き量子化**:
- HuBERT等から抽出したセマンティック特徴を教師信号として活用
- 上位コードブックがセマンティック情報を優先的に保持するよう正則化
- 下位コードブックが音響細部（話者特性・音質）を担当

**マルチストリーム構造**:
- 異なるコードブックを独立したストリームとして処理
- 並列生成・効率的なデコーディングに対応

#### 技術的意義

SoCodec はコーデック設計そのものに「意味的構造」を組み込む設計思想を提示した。CoMelSingerが採用するセマンティック/音響の二段階分離（T2S → S2A）の思想と共鳴している。

---

### 2.6 VoiceCraft

**論文**: "VoiceCraft: Zero-Shot Speech Editing and Text-to-Speech in the Wild" (Peng et al., 2024)
**arXiv**: 2403.16973

#### 概要

VoiceCraft は**音声編集（Speech Editing）**に特化した離散トークンベースモデルで、既存の音声録音の一部を自然に差し替えたり、ゼロショットTTSを実現する。

#### 技術的革新

**因果マスキング（Causal Masking）の工夫**:
```
従来の双方向マスキング: 前後両方のコンテキストを参照
VoiceCraftの因果マスキング: 
  - 編集前の音声 → 通常の因果（左→右）注意
  - 編集区間 → 特殊なマスキングで前後のコンテキストを活用
  - 編集後の音声 → 未来のコンテキストを条件として利用
```

**トークン再配列（Token Rearrangement）**:
- RVQの複数コードブックトークンを適切に再配列して言語モデルに入力
- コードブック間の依存関係を保ちながら自己回帰生成

**"in-the-wild"への対応**:
- 雑音のある実世界音声に対してロバスト
- 大規模なインターネット音声データで訓練

#### CoMelSingerとの関係

VoiceCraft の音声編集思想はCoMelSingerが目指す「プロンプトから話者音色を引き継ぎつつ、メロディは楽譜で制御する」というアプローチと概念的に近い。CoMelSingerはVoiceCraftの編集能力を歌声合成の零点適応に発展させていると解釈できる。

## 3. MaskGCT (参考文献[18])

**論文**: "MaskGCT: Zero-Shot TTS with Masked Generative Codec Transformer" (Wang et al., 2024)
**arXiv**: 2406.06525

### 概要

MaskGCT（**Mask**ed **G**enerative **C**odec **T**ransformer）は**非自己回帰マスク生成**を音声合成に適用し、高品質なゼロショットTTSを実現したフレームワーク。**CoMelSingerの直接的な基盤アーキテクチャ**。

### 非自己回帰マスク生成の仕組み

#### 自己回帰 vs 非自己回帰の比較

```
【自己回帰（AR）モデル: VALL-Eのアプローチ】
生成: [t₁] → [t₂] → [t₃] → ... → [tT]  （逐次生成）
特徴:
  - 各トークンが前のトークンに依存
  - 長距離コンテキストを自然に扱える
  - 推論が遅い（T回のフォワードパスが必要）
  - エラーが蓄積しやすい（exposure bias）

【非自己回帰マスク生成（NAR）: MaskGCTのアプローチ】
生成: [MASK][MASK]...[MASK]  → 全トークンを並列予測
       ↓（高確信度のものから徐々にアンマスク）
      [t₁][MASK]...[t₅][MASK]
       ↓
      [t₁][t₂]...[t₅][t₈]
       ↓ (反復を繰り返す)
      [t₁][t₂]...[tT]        （完成）
特徴:
  - 全トークンが同時に予測可能（並列）
  - 推論が速い（固定回数の反復で完了）
  - 大局的コンテキストを参照しながら生成
  - CoMelSingerが採用
```

#### マスク生成訓練（Masked Generative Training）

訓練時:
```
ターゲット音響トークン列: [a₁, a₂, a₃, a₄, a₅, a₆]

ランダムマスキング:
  [a₁, MASK, a₃, MASK, a₅, MASK]

モデルの目標:
  マスクされたトークン [a₂, a₄, a₆] を予測

損失:
  L_mask = CrossEntropy(予測トークン, 正解トークン)
```

推論時（繰り返しデコーディング）:
```
ステップ1: [MASK, MASK, MASK, MASK, MASK, MASK]  → 全マスク
           モデルが全位置のトークンを予測、確信度スコアを計算

ステップ2: 確信度の高いトークンをアンマスク
           [a₁, MASK, MASK, a₄, MASK, a₆]

ステップ3: 再度予測
           [a₁, a₂, a₃, a₄, MASK, a₆]

...（繰り返し）

最終ステップ: [a₁, a₂, a₃, a₄, a₅, a₆]  完成
```

### MaskGCTのアーキテクチャ

**二段階構造**:

```
[Stage 1: T2S（Text-to-Semantic）]
入力: テキスト + セマンティックプロンプト
出力: セマンティックトークン列

モデル: Masked Generative Transformer (LLaMA-style)
処理: テキストからセマンティックトークンを非自己回帰生成

     ↓

[Stage 2: S2A（Semantic-to-Acoustic）]
入力: セマンティックトークン + 音響プロンプト
出力: 音響トークン列（EnCodec 8コードブック）

モデル: Masked Generative Transformer (DiffLlama-style)
処理: セマンティックトークンから音響トークンを非自己回帰生成
```

**大局的コンテキスト参照の利点**:
非自己回帰生成では全トークン位置を同時に参照できるため、自己回帰の「左から右への一方向参照」に比べて大局的なコンテキスト（文全体のリズム・抑揚の流れ）を考慮した生成が可能。

### CoMelSingerがMaskGCTを拡張する方法

CoMelSingerは次の点でMaskGCTを拡張・改良している（論文 Section III.B より）:

#### 拡張1: ピッチ条件付け

```
MaskGCT の S2A 入力:
  [セマンティックトークン] + [音響プロンプト]

CoMelSinger の S2A 入力:
  [セマンティックトークン] + [ピッチトークン m^p] + [デュレーション m^d] + [音響プロンプト]
```

ピッチトークン `m^p` の条件付けにより、楽譜から指定されたメロディラインに従った歌声生成が可能になる。

**ピッチ埋め込みの追加**:
```
論文 Section III.B より:
"pitch embedding e_p is element-wise added to the semantic 
token embedding e_s for the compound conditioning input..."
```

セマンティックトークン埋め込みにピッチ埋め込みを要素ごとに加算することで、音高情報をS2Aモジュールの全処理に織り込む設計。

#### 拡張2: SVTによる補助監視

```
MaskGCT: 音響プロンプトから話者音色を学習（暗黙的）

CoMelSinger: SVT（Singing Voice Transcription）モジュールを追加
  - SVTは音響トークン列からピッチトークン列を予測するよう学習
  - 訓練済みSVTを凍結し、S2A訓練中の補助監視信号として使用
  - SVT損失: L_SVT = CrossEntropy(SVT予測ピッチ, ターゲットピッチ)
```

SVTはS2Aが生成した音響トークンが、意図したメロディラインを正しく反映しているかを評価する「ピッチ整合性チェッカー」として機能する。

#### 拡張3: 対照学習によるプロソディ漏洩防止

```
MaskGCT の問題（CoMelSinger論文 Section I. で指摘）:
  音響プロンプトから「プロソディ漏洩」が発生
  = 話者の音高・リズム癖が生成音声に意図せず反映される
  
CoMelSinger の対処:
  粗-細 対照学習（Coarse-to-Fine Contrastive Learning）で
  音高情報とティンバー（音色）を分離
```

### CoMelSingerのアルゴリズム（Algorithm 1）

論文のAlgorithm 1を基に、S2A微調整プロセスを整理する:

```
入力:
  - S2A モデルパラメータ θ（MaskGCT初期化）
  - 凍結SVTモデル f_SVT
  - 損失重み λ_CL, λ_SVT, λ_mask
  - エポック数 N

各エポック、各バッチで:
  1. バッチ B = {x₁,...,xₖ} をサンプリング
  2. B を B^S（同一話者）と B^A（任意話者）に分割
  3. 条件付けプロンプト a', e' を生成
  4. フォワードパス:
     e = f_S2A(B)          ← セマンティック埋め込み
     e = f_S2A(B')         ← プロンプト埋め込み
     e を K個に分割: e_K（セマンティック埋め込み）
     g^s = AvgPool(g^s)    ← 系列レベルグローバル表現
     g^f = AvgPool(g^f)    ← フレームレベルグローバル表現
  5. 損失計算:
     L_SCL = SCL損失（系列レベル対照）
     L_FCL = FCL損失（フレームレベル対照）
     L_CL = SCL + FCL
     a^ = f_head(ā)        ← マスクされたトークン予測
     L_mask = MaskLoss(ā, a)
     m^p = f_SVT(StopGrad(ā))  ← SVT補助損失
     L_SVT = CrossEntropy(m^p, m^p_in)
     L = λ_CL·L_CL + λ_SVT·L_SVT + λ_mask·L_mask
  6. パラメータ更新: θ ← θ - η·∇_θ·L
```

## 4. セマンティックトークン

### 概要

セマンティックトークン（Semantic Tokens）は、音声から**言語的・意味的内容**（what is said）を捉えた離散表現であり、音響的詳細（音色・音質・話者特性）を含まない。音声処理においてコンテンツ表現と音響表現を分離する手段として不可欠。

### 4.1 wav2vec 2.0

**論文**: "wav2vec 2.0: A Framework for Self-Supervised Learning of Speech Representations" (Baevski et al., 2020, NeurIPS)

#### アーキテクチャ

```
入力: 生音声波形

[特徴エンコーダ]
  7層畳み込みネットワーク
  音声波形 → 潜在特徴 z（20ms フレーム）
  
  ↓

[量子化モジュール]
  Gumbel-softmax + 2コードブック
  潜在特徴 z → 量子化表現 q（離散トークン候補）
  
  ↓（一部をマスク）

[コンテキストネットワーク]
  Transformer（12〜24層）
  マスクされた位置でのコンテキスト表現 c

訓練目標: コントラスティブ損失
  マスク位置で正解の量子化表現 q を他のダミーから識別
```

#### 自己教師あり学習の意義

wav2vec 2.0 はラベルなし音声データのみで意味豊かな表現を学習する。大量の未ラベル音声（LibriSpeech等）で事前学習後、少量のラベル付きデータでファインチューニングすることでASR等のタスクを解ける。

### 4.2 HuBERT

**論文**: "HuBERT: Self-Supervised Speech Representation Learning by Masked Prediction of Hidden Units" (Hsu et al., 2021)

#### 学習の仕組み

```
[訓練フェーズ1]
  オフライン K-meansクラスタリング（MFCC特徴から）
  → 擬似ラベル（k-meansクラスタID）を生成
  
  Transformer を訓練:
    マスクされた音声フレームの擬似ラベルを予測
    （BERTと同様の masked prediction）

[訓練フェーズ2]
  フェーズ1のHuBERTの中間層出力に対してK-meansを適用
  → 改良された擬似ラベルを生成
  
  HuBERTをより精緻なラベルで再訓練
```

**音声のBERT**と称されるHuBERTは、音素・単語レベルの情報を階層的に捉えた表現を学習する。

#### セマンティックトークンとしての利用

```
HuBERT 最終層（または中間層）の特徴量
  ↓
K-meansクラスタリング（クラスタ数 K = 100 〜 500）
  ↓
各フレームのクラスタID → セマンティックトークン
```

HuBERTから得られるセマンティックトークンは：
- 音素情報を豊かに含む
- 話者特性（音色）からある程度独立
- TTSのコンテンツ表現として広く使われる

### 4.3 Whisper

**論文**: "Robust Speech Recognition via Large-Scale Weak Supervision" (Radford et al., 2022, OpenAI)

#### 特性とセマンティックトークンへの応用

Whisper は大規模弱教師あり学習による音声認識モデルで、68万時間の多言語音声で訓練される。

```
Whisperエンコーダ出力（音響特徴）
  ↓
K-meansクラスタリング
  ↓
セマンティックトークン
```

**wav2vec/HuBERTとの違い**:

| モデル | 訓練方式 | 主な情報 | 言語対応 |
|:---|:---|:---|:---|
| wav2vec 2.0 | 自己教師あり対照学習 | 音素・音響 | 英語中心 |
| HuBERT | 自己教師あり masked prediction | 音素・意味 | 英語中心 |
| Whisper | 弱教師あり（転写データ） | 意味・言語 | 多言語 |

CLAUDE.md より:
> Semantic features: wav2vec-based (from Whisper/S3PRL)

CoMelSingerはWhisperから抽出したセマンティック特徴を使用していることがわかる。

### 4.4 K-meansクラスタリングによる離散化

#### 手順

```
[事前学習済みモデルからの特徴抽出]
  音声ファイル → HuBERT/Whisper エンコーダ
  → フレームごとの連続特徴ベクトル h ∈ ℝ^D
  （Dは特徴次元数: 256〜1024）

[K-meansクラスタリング（オフライン）]
  大量の特徴ベクトルに対して K-means を実行
  クラスタ数 K（典型値: 100, 200, 500, 1000）
  → K個のクラスタ中心 {μ₁, μ₂, ..., μₖ} を求める

[トークン化（オンライン）]
  新しい音声 → 特徴抽出 → h
  h に最も近いクラスタ中心のインデックスを割り当て
  → セマンティックトークン（整数インデックス）
```

#### トークンの性質

```
連続表現（HuBERT出力）:
  [h₁: 0.23, -0.15, 0.87, ...]  ← 512次元浮動小数点数
  [h₂: 0.31, -0.12, 0.79, ...]
  ...

離散セマンティックトークン（K-means後）:
  [s₁: 47]   ← クラスタID（整数）
  [s₂: 47]   ← 同じクラスタ（/i/ 音素など）
  [s₃: 183]  ← 異なるクラスタ（/a/ 音素など）
  ...
```

**重複トークンの処理**:
連続する同一トークンは通常デデュープ（重複除去）される:
```
元の系列: [47, 47, 47, 183, 183, 95, 95, 95, 95]
デデュープ後: [47, 183, 95]  ← シーケンス長を大幅短縮
```

これにより言語モデルへの入力系列長を削減し、計算効率を向上させる。

#### CoMelSingerでの役割

```
論文 Section III.A より:
"The T2S module f_{T2S} transforms a lyric token sequence 
n^s = [n^s_1,...,n^s_{L_n}], where V_{sem} denotes the 
semantic vocabulary and L the sequence length."

セマンティックトークンは：
  - T2S: テキスト → セマンティック変換の「中間表現」
  - S2A: セマンティック → 音響変換の「入力」
として機能する、CoMelSingerの二段階パイプラインの結節点。
```

## 5. 対照学習の音声分野での応用

### 対照学習の基本原理

**対照学習（Contrastive Learning）**は、類似したサンプルペア（正例ペア）を近くに、異なるサンプルペア（負例ペア）を遠くに埋め込むことで、意味のある表現を学習する自己教師あり学習手法。

```
正例ペア（同一話者の異なる発話）:
  anchor ──── positive  ← 埋め込み空間で近くに
  
負例ペア（異なる話者の発話）:
  anchor          
           ∣
           ∣ (遠ざける)
           ∣
        negative  ← 埋め込み空間で遠くに

損失（InfoNCE / NT-Xent）:
L = -log[ exp(sim(anchor, positive)/τ) /
          Σ_j exp(sim(anchor, negative_j)/τ) ]
```

ここで `τ` は温度パラメータ、`sim` はコサイン類似度等の類似度関数。

### 5.1 CLAP-Speech (参考文献[56])

**関連論文**: CLAP (Contrastive Language-Audio Pre-training) 系統の音声応用

#### CLAP の基本構造

CLAP（元来は音楽・音響イベント記述向け）の音声合成への応用:

```
テキストエンコーダ（BERTなど）:
  テキスト → テキスト埋め込み e_T

音声エンコーダ（wav2vec等）:
  音声 → 音声埋め込み e_A

対照学習目標:
  同一内容の（テキスト, 音声）ペア → e_T と e_A を近づける
  異なる内容のペア → 遠ざける
```

#### 音声合成での応用

CLAP-Speech は音声合成モデルに対して：
- 生成音声がテキストプロンプトの意図と一致しているかを検証
- 多様な話者・スタイルにわたって意味的に一貫した表現を学習
- ゼロショット条件での表現力向上に貢献

```
CoMelSinger論文 Section III.C で言及:
「CLAP-Speech [56] はマルチスケール対照学習で音声・
  テキスト間の表現空間を統合し、多様なテキストアクロスの
  表現力向上と推論一般化の改善に貢献」
```

### 5.2 CTAP (参考文献[61])

**論文**: "Contrastive Context-Speech Pretraining for Expressive Text-to-Speech" (Qiang et al., 2024)

#### 概要

CTAP（**C**ontrastive **T**ext-**A**udio **P**retraining）はテキストコンテキストと音声ペアに対する対照学習事前学習を提案し、表現力豊かなTTSのための音声埋め込みを学習する。

#### 技術的詳細

```
入力ペア: (テキストコンテキスト, 音声)

テキスト側: BERT/RoBERTa で文書コンテキストをエンコード
音声側:   音声エンコーダで音響特徴をエンコード

対照目標:
  - 同じ文の文脈を持つ（テキスト, 音声）ペア → 近くに
  - 異なる文脈のペア → 遠くに

学習される表現:
  - 韻律（プロソディ）を豊かに捉えた音声埋め込み
  - テキストから推論可能な発話スタイルを学習
```

**CTPAの貢献**:
- テキストコンテキストから自然な韻律を生成する能力を向上
- 限定的な韻律ラベルでも表現力ある音声合成を実現

### 5.3 CoMelSingerにおける対照学習の設計

CoMelSingerは上記の研究を踏まえ、**歌声特有の課題**（プロソディ漏洩）に対処する独自の対照学習戦略を設計した。

#### 問題設定: プロソディ漏洩

```
音声プロンプト（参照音声）
  ↓
MaskGCT（従来）
  ↓
生成音声 ← 話者音色 + 【意図しないメロディ漏洩】

プロソディ漏洩 = プロンプトの音高・リズムが
                生成音声に混入する現象
                歌声合成では致命的
                （楽譜の指定メロディが正確に反映されない）
```

#### 粗-細 対照学習（Coarse-to-Fine Contrastive Learning: CL）

CoMelSingerは2段階の対照学習で音高とティンバーを分離する（論文 Section III.C）:

**Stage 1: 系列レベル対照学習（SCL: Sequence-Level CL）**

```
バッチ内の K サンプル:
  s = {(m^s_k, m^p_k)}_{k=1}^K  ← セマンティック + ピッチペア
  
セマンティックトークン埋め込み g^s:
  g^s = AvgPool(f_{S2A}(m^s))  ← 系列全体を平均プール

ピッチトークン埋め込み g^p:
  g^p = AvgPool(m^p の埋め込み)

SCL損失（論文 式(3)）:
L_SCL(g^s, g^p) = 対称対照損失

目的: 同一サンプルの (g^s, g^p) を近づけ、
     異なるサンプルのペアを遠ざける
     → 系列全体のメロディ輪郭整合性を学習
```

**Stage 2: フレームレベル対照学習（FCL: Frame-Level CL）**

```
セマンティック埋め込み f = e_{K_s:K}  ← フレーム単位の特徴
ピッチ埋め込み f^p = e'_{K_{s+1}:K}  ← フレーム単位のピッチ

ソフトラベルマトリクス Y（論文 式(4)）:
Y_{i,j} = 1 if m^p_i == m^p_j  (同一ピッチラベル)
         = 0 otherwise

FCL損失（論文 式(5)）:
L_FCL = ソフトラベル対照損失（ピッチパディング・繰り返しを考慮）

目的: 同一ピッチのフレーム同士を近づけ、
     異なるピッチのフレームを遠ざける
     → フレーム単位のピッチ一貫性を学習
```

**ソフトラベルを使う理由**:
```
歌声のピッチは持続音（サステイン）が多く、
同一ピッチが連続するフレームが大量に存在する。
ハードラベル（0/1）では同一ピッチのフレームが
全て「同一」とみなされ、音楽的に無意味な類似度学習になる。
ソフトラベルにより、持続音フレームの自然なグルーピングを実現。
```

**損失関数の統合**:
```
L_CL = L_SCL + L_FCL

総合訓練損失:
L = λ_CL · L_CL + λ_SVT · L_SVT + λ_mask · L_mask

論文の設定:
  λ_CL = 1.0, λ_SVT = 1.0, λ_mask = 0.5
```

#### アブレーション実験による効果確認

論文 Table V（アブレーション研究）:

| 設定 | MCD↓ | F0-RMSE↓ | SingMOS↑ | SECS↑ |
|:---|:---:|:---:|:---:|:---:|
| CoMelSinger（全損失） | **4.17** | **0.042** | **4.32** | **0.912** |
| -w/o SCL（系列レベルCL除去） | 4.53 | 0.062 | 4.25 | 0.900 |
| -w/o FCL（フレームレベルCL除去） | 4.82 | 0.075 | 4.18 | 0.892 |
| -w/o SVT（SVT損失除去） | 5.19 | 0.194 | 3.95 | 0.883 |
| -w/o CL+SVT（全補助損失除去） | 5.89 | 0.210 | 3.83 | 0.874 |

SCL は全体的なメロディ輪郭整合性を担い（MCD・SECS改善）、FCL はフレーム単位のピッチ細部と音色の分離を担う（F0-RMSE・SingMOS改善）という相補的な役割が確認された。

## 6. CoMelSingerにおける統合的な位置付け

### アーキテクチャ全体の技術的系譜

```
【先行技術の系譜】

ニューラルコーデック系列:
  SoundStream (2021) → EnCodec (2022) → DAC (2023)
                              ↓
                      CoMelSinger が採用（8-RVQ）

離散トークンTTS系列:
  VALL-E (2023) → VALL-E 2 (2024) → VALL-E R (2024)
       ↓（並列化・高速化の流れ）
  SoundStorm (2023)
       ↓
  MaskGCT (2024) ←── CoMelSinger の直接基盤

セマンティックトークン:
  wav2vec 2.0 (2020) → HuBERT (2021) → Whisper (2022)
                              ↓
                      CoMelSinger が採用（Whisper/S3PRL）

対照学習:
  CLAP (2022) → CLAP-Speech → CTAP (2024)
                      ↓
             CoMelSinger の粗-細 CL 設計に影響
```

### 各技術コンポーネントの役割まとめ

| 技術コンポーネント | 役割 | CoMelSingerでの具体的利用 |
|:---|:---|:---|
| EnCodec (8-RVQ) | 音声の離散トークン化 | S2A の音響トークン生成・デコード |
| Whisper/wav2vec | セマンティック特徴抽出 | T2S のセマンティックトークン供給 |
| K-meansクラスタリング | 連続特徴の離散化 | セマンティックトークン生成 |
| MaskGCT (T2S+S2A) | 非自己回帰マスク生成 | 全体パイプラインの基盤アーキテクチャ |
| SVT モジュール | ピッチ補助監視 | フレームレベルF0整合性の確保 |
| 粗-細 CL（SCL+FCL） | 音高-ティンバー分離 | プロソディ漏洩の防止 |
| ソフト持続時間損失 | 時間的整合性 | ピッチトークン確率分布の時間制約 |
| LoRA | 効率的ファインチューニング | 少ないパラメータ更新でドメイン適応 |

### CoMelSingerの技術的貢献

論文が主張する主要な技術的新規性は以下の3点:

1. **構造化メロディ制御**: ピッチトークンと持続時間情報を明示的に条件として組み込み、楽譜からの精密なピッチ制御を実現（従来のSVSは暗黙的なF0制御）

2. **粗-細 対照学習**: 系列レベル + フレームレベルの2段階対照学習でプロソディ漏洩を防止。これはゼロショット音声合成でプロンプト音声の音色のみを引き継ぎ、メロディは楽譜に従わせるために不可欠

3. **軽量SVT監視**: 事前訓練・凍結したSVTモジュールを補助監視として使用することで、外部アライメントモデルを必要とせず、フレームレベルのピッチ整合性を達成

### 実験結果での位置付け

論文 Table II（見出し歌声合成評価）での CoMelSinger の達成結果:

| 指標 | CoMelSinger | 最高競合モデル |
|:---|:---:|:---:|
| MOS-Q（音声品質） | 3.90 | Veso 1.5 (3.85) |
| F0-RMSE（ピッチ精度） | **0.042** | 最良 |
| SingMOS（歌声自然性） | **4.32** | Veso 1.5 (4.39) |
| SECS（話者類似度） | **0.912** | 最良 |

ゼロショット設定（Table III）でも競合システムと比較して優れた結果を示しており、離散トークンベースアーキテクチャの有効性を実証している。
