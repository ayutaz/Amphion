# SVT（Singing Voice Transcription）モジュールとピッチ制御メカニズム

CoMelSinger論文（arXiv:2509.19883v2）に基づく詳細解説

---

## 1. SVTモジュールの目的と設計思想

### 1.1 ピッチガイダンスの必要性

歌声合成（SVS）は、テキスト読み上げ（TTS）と異なり、**ピッチと持続時間が楽譜によって厳密に規定される**という特性を持つ。この制約により、SVSにはTTSとは異なる独自の課題が生じる。

離散コードベースのSVSにおける中心的な問題のひとつが**プロンプト誘発によるプロソディ漏洩**である。インコンテキスト生成において、音声プロンプトはモデルが音色や話者スタイルを模倣するための参照として機能する。しかし、プロンプトが本来意図するタイムブレ（音色・話者性）情報だけでなく、**ピッチ・リズム・メロディ輪郭などのプロソディ情報をも暗黙的に引き込んでしまう**ことが実験的に確認されている。

Table I に示されるとおり、ペアード条件（同一話者のプロンプト）とアンペアード条件（異なる話者のプロンプト）を比較すると、ペアード条件のほうがピッチ平均・エネルギー平均・ジッターなどのプロソディ指標で常に低い差異（高い類似性）を示す。これはモデルがプロンプトから音色だけでなくピッチパターンも学習していることを意味し、**楽譜で指定されたピッチからの逸脱**を引き起こす。

歌声において「ピッチと持続時間は楽譜によって支配されるべきもの」であるにもかかわらず、プロンプトからのプロソディ漏洩はこの大原則を損なう。そこでCoMelSingerは、**ピッチガイダンスを独立したモジュールとして明示的にシステムに組み込む**アーキテクチャを採用する。

### 1.2 なぜ独立したSVTモジュールを導入するのか

先行研究でもSVSへのピッチ制御は試みられてきた。しかしその多くは、以下の問題点を抱えていた。

- **外部デュレーション予測器や補助アライメントモジュールへの依存**：アーキテクチャ上のオーバーヘッドが大きく、一般化が困難。
- **独立前処理としてのSVT利用**：SVTをS2A（Semantic-to-Acoustic）学習から切り離すと、両者の情報が整合しない。
- **プロンプトベース合成でのピッチ制御の欠如**：ゼロショット合成において、楽譜由来のメロディ制御が不十分。

CoMelSingerが採用する解決策は、**SVTモジュールをS2Aモデルの補助監督器（auxiliary supervisor）として学習フレームワーク内に統合する**ことである。

具体的には：

1. SVTモジュールを**先に独立して学習**し、精度の高いピッチトークン予測器を構築する。
2. S2A学習フェーズでは、SVTモジュールのパラメータを**凍結（frozen）**したまま、補助監督信号（auxiliary supervision）として機能させる。
3. これにより、S2Aモデルは「楽譜から期待されるピッチ輪郭に沿った音響トークンを生成する」という暗黙の圧力を受けながら学習する。

このアプローチにより、追加の推論時オーバーヘッドや外部アライメント構造なしに、**ピッチ制御を学習目標として内部化**できる。

## 2. SVTモジュールのアーキテクチャ

### 2.1 軽量エンコーダ専用Transformer

SVTモジュールは**軽量なエンコーダ専用Transformer**として設計されている。その設計方針は以下のとおり：

- **エンコーダのみ（decoder不要）**：入力系列を受け取り、各フレームに対してピッチクラスを予測する分類タスクとして定式化されている。
- **軽量設計**：S2Aモデル本体とは独立して動作し、凍結後も計算コストを最小限に抑える。

### 2.2 Transformerの主要ハイパーパラメータ

| パラメータ | 値 |
|---|---|
| Transformerレイヤー数 | 4層 |
| 隠れ次元数（hidden size） | 512 |
| アテンションヘッド数 | 8 |

### 2.3 入出力の定義

**入力**：音響トークン列 $\mathbf{a} \in \mathbb{R}^{L \times D}$

- S2Aモデルによって生成・使用される離散音響コード列。
- 各トークンは512次元の離散コードブック空間に属する。

**出力**：ピッチトークン列 $\hat{\mathbf{m}}^p \in \mathbb{R}^{L \times C}$

- 各フレームに対して予測されたピッチクラスの確率分布（softmax後）。
- $C$ はピッチ語彙サイズ（ピッチトークンの種類数）。
- $L$ はフレーム数（系列長）。

### 2.4 内部表現：512次元への変換と連結

SVTモジュール内部での特徴変換は以下の手順で行われる：

1. **埋め込み（Embedding）**：入力音響コードの各離散インデックスをルックアップテーブルによって連続ベクトルに変換する。
2. **次元投影**：各音響コードブックからの埋め込みを連結（concatenate）し、線形変換によって**512次元の統一表現**に射影する。
3. **Transformer処理**：512次元のフレーム系列を4層Transformerに入力し、文脈を考慮した表現を獲得する。
4. **分類ヘッド**：最終層の出力をピッチ語彙サイズ $C$ に対応するlogitsに変換し、softmaxによって確率分布を得る。

この設計により、複数の音響コードブックにまたがる情報が512次元空間で統合され、フレームレベルのピッチ予測が可能になる。

## 3. SVTの学習

SVTモジュールは3種類の損失関数の組み合わせによって学習される。

### 3.1 総合損失

$$\mathcal{L}_{\text{SVT}} = \mathcal{L}_{\text{CE}} + \lambda_{\text{seg}} \cdot \mathcal{L}_{\text{seg}} + \lambda_{\text{dur}} \cdot \mathcal{L}_{\text{dur}} \tag{9}$$

ここで：
- $\lambda_{\text{seg}}$：セグメント遷移損失の重み係数
- $\lambda_{\text{dur}}$：ソフトデュレーション損失の重み係数

### 3.2 Cross-entropy Loss（$\mathcal{L}_{\text{CE}}$）

フレームごとのピッチクラス分類のための基本損失。予測されたピッチトークン $\hat{\mathbf{m}}^p$ とグラウンドトゥルースのピッチトークン $\mathbf{m}^p$ の間のクロスエントロピーとして定義される。

$$\mathcal{L}_{\text{CE}} = -\sum_{t=1}^{L} \log \hat{p}_t[m^p_t]$$

ただし、$\hat{p}_t[m^p_t]$ はフレーム $t$ における正解ピッチクラス $m^p_t$ の予測確率。

### 3.3 Segment Transition Loss（$\mathcal{L}_{\text{seg}}$）— 数式(7)の詳細

$$\mathcal{L}_{\text{seg}} = \sum_{t=2}^{L} \left[ (1 - b_t) \cdot \|\mathbf{p}_t - \mathbf{p}_{t-1}\|^2 + b_t \cdot \max(0, \delta - \|\mathbf{p}_t - \mathbf{p}_{t-1}\|^2) \right] \tag{7}$$

各項の意味：

| 記号 | 定義 |
|---|---|
| $b_t$ | バイナリ境界指示子。$b_t = \mathbb{1}[m^p_t \neq m^p_{t-1}]$（グラウンドトゥルースのピッチ境界で1） |
| $\mathbf{p}_t$ | フレーム $t$ における予測ピッチ確率分布ベクトル |
| $\delta$ | 境界での乖離を促すマージンハイパーパラメータ |

**第1項（境界内の連続性）**：$b_t = 0$（同一ピッチセグメント内）のとき、隣接フレームの予測分布が近似するよう促す。同一音符内でのフレーム間変動を抑制し、**セグメント内の一貫性**を維持する。

**第2項（境界での不連続性）**：$b_t = 1$（ピッチ境界）のとき、隣接フレームの予測分布の距離が $\delta$ 未満なら損失が発生する。音符の切れ目で**十分な対比**が生まれるよう促し、境界をまたいだ予測の鮮明化を図る。

この損失の設計思想：クロスエントロピー単体では**ピッチ変化点での明確な区切り**が保証されない。$\mathcal{L}_{\text{seg}}$ は、ピッチセグメント内では平滑で、セグメント境界では急峻な確率分布を形成させることで、音節境界の認識精度と合成の表現力を高める。

### 3.4 Soft Duration Loss（$\mathcal{L}_{\text{dur}}$）— 数式(8)の詳細

$$\mathcal{L}_{\text{dur}} = \sum_{i=1}^{S} \left( \sum_{t=T_i}^{T_i + a^d_i - 1} \mathbf{p}_t[m^p_i] - a^d_i \right)^2 \tag{8}$$

各項の意味：

| 記号 | 定義 |
|---|---|
| $S$ | ピッチトークン（音符）の総数 |
| $i$ | $i$番目のピッチトークン（音符）のインデックス |
| $m^p_i$ | $i$番目のピッチトークンのクラスラベル |
| $T_i$ | $i$番目のピッチトークンの開始フレームインデックス。$T_i = \sum_{j=1}^{i-1} a^d_j$ |
| $a^d_i$ | $i$番目のピッチトークンに割り当てられた持続フレーム数（フレームレベルアライメント） |
| $\mathbf{p}_t[m^p_i]$ | フレーム $t$ での正解ピッチクラス $m^p_i$ の予測確率 |

**直感的解釈**：$i$番目の音符が占める $a^d_i$ フレームにわたって、モデルがそのピッチクラス $m^p_i$ に割り当てる確率の総和が、フレーム数 $a^d_i$ に近くなるよう（すなわち、各フレームで平均的に確率1を割り当てるよう）学習する。

$\mathcal{L}_{\text{dur}}$ の設計思想：クロスエントロピーは各フレームの正解確率を最大化するが、音符単位での「正しいフレーム数にわたって正しいピッチを維持する」という時間的整合性は保証しない。ソフトデュレーション損失は**確率質量を各ピッチトークンに適切に配分**する外部監督なしに、時間軸方向の一貫性を強制する。これにより、デュレーション予測器などの補助構造を必要とせず、S2Aモデルがリズム整合性の高い音響特徴を生成できるようになる。

## 4. ピッチトークンの設計

### 4.1 F0からの離散化方法

ピッチトークンは、連続的な基本周波数（F0）を離散化することで得られる。

SVTモジュールへの入力として用いるグラウンドトゥルースのピッチ系列 $\mathbf{m}^p$ は、**記号的デュレーション系列** $\mathbf{m}^d = [m^d_1, \ldots, m^d_S]$ から構築される。ここで各 $m^d_i$ は $i$番目の音符の持続時間（シンボル長）を示す。

論文では、MakGCT と同様のフレームワーク上でピッチ音響トークンコードブックを構築する。具体的には楽譜のノートピッチを離散カテゴリとして扱い、音符ごとのF0クラスに対応するトークンインデックスを生成する。

### 4.2 ピッチ語彙サイズ $C$

ピッチトークンの語彙サイズは $C$ で表される。論文では音響コードブックに 512 次元の離散表現を用いており、ピッチ語彙はMakGCTの音響コードブック設計に準拠して構築される。実験的には24kHzでサンプリングされた音声を16ビット量子化で処理し、ピッチ分解能として440Hzを基準音とする対数スケールの128段階相当の離散化が基礎となっている。

### 4.3 フレームレベルのアライメント（$a^d$ の計算方法）

シンボリックデュレーション $\mathbf{m}^d = [m^d_1, \ldots, m^d_S]$ をフレームレベルのアライメント $\mathbf{a}^d = [a^d_1, \ldots, a^d_S]$ に変換する手順：

1. **全フレーム数の計算**：$D = \sum_{i=1}^{S} m^d_i$（全音符のシンボル長の総和）、$L$は音響特徴系列の総フレーム数。

2. **正規化アライメントの計算**：各音符のフレーム数を以下の式で求める。

$$a^d_i = \left\lfloor \frac{m^d_i}{D} \cdot L \right\rfloor$$

ここで $L$ は音響特徴系列の総フレーム数、$D$ は全シンボル長の総和。

3. **フレーム整合性の確保**：このように定義することで $\sum_i a^d_i = L$ が成立し、音符系列と音響特徴系列が過不足なくアライメントされる。

4. **ピッチ整列系列の生成**：上記アライメントに基づき、フレームアラインドなピッチ系列 $\mathbf{m}^{p,\text{aligned}}$ を構築する。論文では以下の定式化を用いる。

$$h_{\text{start}} = h_{\text{end}} = k_{\text{start}} = 0, \quad c_i = \sum_{j=1}^{i} m^d_j / D$$

フレームアラインドなピッチトークン系列 $\tilde{\mathbf{m}}^p$ は、累積正規化デュレーション $c_i$ を丸めることでフレーム境界を決定し、対応する音符ピッチラベルを各フレームに割り当てることで構築される。

## 5. SVTモジュールのS2A学習時の役割（Frozen Auxiliary Supervisor）

### 5.1 二段階学習戦略

CoMelSingerは以下の2フェーズ学習を採用する。

**フェーズ1：SVTの独立学習**

SVTモデルは $\mathcal{L}_{\text{CE}}$、$\mathcal{L}_{\text{seg}}$、$\mathcal{L}_{\text{dur}}$ の組み合わせにより独立して学習される。このとき訓練済みの前処理音響コードモデルを使い、音響トークン列から高精度なピッチトークン予測器を構築する。学習の最適化にはAdamWオプティマイザを使用し、学習率 $1 \times 10^{-5}$、重み減衰 $0.01$ で設定される。バッチサイズ32で100エポック学習する。

**フェーズ2：S2AモデルのFine-tuning（SVT凍結）**

Algorithm 1 に示されるとおり、S2A学習時のSVT損失計算は次のように組み込まれる：

```
20: m^p ← f_SVT(StopGrad(a))
21: Compute L_SVT from m^p and m̃^p according to (9)
```

`StopGrad(a)` は、SVT損失の勾配がS2A生成した音響トークン $\mathbf{a}$ を通じてS2Aのエンコーダに逆伝播しないようにする操作。これにより：

- SVTモジュール自体のパラメータは更新されない（**凍結**）。
- S2Aモデルは、自身が生成した音響トークンが「SVTにとって正しいピッチ予測を生じさせるか」という間接的な信号を受け取り、**ピッチ整合性の高い音響トークンを生成するよう学習**される。

### 5.2 S2A学習の総合損失におけるSVT損失の位置づけ

S2A Fine-tuningの総合損失は次の通り：

$$\mathcal{L} = \lambda_{\text{CL}} \cdot \mathcal{L}_{\text{CL}} + \lambda_{\text{SVT}} \cdot \mathcal{L}_{\text{SVT}} + \lambda_{\text{mask}} \cdot \mathcal{L}_{\text{mask}}$$

各損失の役割：

| 損失 | 役割 |
|---|---|
| $\mathcal{L}_{\text{mask}}$ | マスクトークン予測損失。ノイズ入力から音響トークンを再構成する自己教師あり損失 |
| $\mathcal{L}_{\text{CL}}$ | コントラスティブ損失。系列レベル（$\mathcal{L}_{\text{SCL}}$）とフレームレベル（$\mathcal{L}_{\text{FCL}}$）の組み合わせ |
| $\mathcal{L}_{\text{SVT}}$ | **SVT補助損失**。凍結SVTモジュールから得られる $\mathcal{L}_{\text{CE}} + \lambda_{\text{seg}} \mathcal{L}_{\text{seg}} + \lambda_{\text{dur}} \mathcal{L}_{\text{dur}}$ |

論文中で採用されたハイパーパラメータ：

$$\lambda_{\text{SCL}} = 0.5, \quad \lambda_{\text{FCL}} = 1.0, \quad \lambda_{\text{CL}} = 0.1, \quad \lambda_{\text{seg}} = 0.5, \quad \lambda_{\text{dur}} = 0.5$$

### 5.3 SVT凍結の技術的意義

凍結SVTを補助監督器として使用することの利点：

1. **プロソディ漏洩の抑制**：S2Aモデルが音響プロンプトから誤ってピッチ情報を引き込む傾向を、SVT損失が対抗することで軽減する。

2. **追加の推論コスト不要**：SVTは学習時のみ使用され、推論時にはS2Aモデル単体で動作する。

3. **外部アライメント構造の不要化**：デュレーション予測器や外部アライメントモデルなしに、楽譜整合性の高い合成が可能。

4. **離散表現との親和性**：SVTの入出力がともに離散トークン空間で定義されるため、既存の離散コードベースS2Aフレームワーク（MakGCT等）に自然に統合できる。

実験結果（Table III・IV）では、SVT情報付きモデルがF0-RMSEでRMSingerを上回る性能を達成し、ピッチ精度においてCoMelSingerが最高スコアを記録している（F0-RMSE: 0.048）。これはSVTによる補助監督が実際にピッチ制御の精度向上に寄与していることを定量的に示している。

SVTモジュールは学習時にのみ音響トークン列 $\mathbf{a}$ を受け取り、予測ピッチトークン $\hat{\mathbf{m}}^p$ を生成してターゲットピッチ $\tilde{\mathbf{m}}^p$ と比較することで、S2Aモデルへの監督信号 $\mathcal{L}_{\text{SVT}}$ を提供する。推論時にはSVTモジュールは使用されず、S2Aモデルが直接音響トークン列を生成する。
